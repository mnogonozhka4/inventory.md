## 1. Что за проект
ScalpelJS - это легковесная экосистема для создания современных веб-приложений на основе Web Components, при этом большая часть кода остается на чистом Vanilla JavaScript. Проект решает проблему тяжелых абстракций (таких как Virtual DOM) и предлагает точечные, предсказуемые обновления реального DOM без использования шаблонных компиляторов.

## 2. Кто им пользуется
Основная аудитория — это разработчики, которые предпочитают нативные технологии браузера и хотят иметь тонкий контроль над DOM.

| Группа | Что ей нужно от документации |
| :--- | :--- |
| **Разработчик (пользователь библиотеки)** | Как установить, как создать первый компонент, как работает реактивность. |
| **Фронтенд-разработчик** | Как использовать роутер (`jong-router`), формы (`pao-form`) и стейт-менеджер (`redgin-store`). |
| **Контрибьютор (участник проекта)** | Как устроен код, как запустить тесты, как внести свой вклад. |

## 3. Что уже есть
В репозитории уже присутствует следующая документация:
*   **`README.md`** - основной файл с описанием философии проекта, быстрым стартом (`npx create-scalpeljs@latest`) и списком пакетов экосистемы.
*   **Папка `docs`** - содержит дополнительную документацию (но в ней мало информации).
*   **Примеры в README** - есть базовые команды для установки и запуска.

## 4. Чего не хватает
При изучении проекта остались без ответа следующие вопросы:
1.  **API Reference:** Нет подробного описания методов и свойств библиотек `redgin`, `jong-router`, `pao-form`.
2.  **Примеры кода:** В README нет ни одного примера того, как выглядит код компонента на ScalpelJS. Непонятно, как именно писать логику.
3.  **Документация по миграции:** Если я использую обычный Vanilla JS, как мне перейти на ScalpelJS? Пошаговой инструкции нет.
4.  **Тонкости настройки:** Как настроить сборку (Vite) вручную, если я не хочу использовать `create-scalpeljs`? В README есть только команда `npm install scalpeljs`, но что делать дальше - неясно.
